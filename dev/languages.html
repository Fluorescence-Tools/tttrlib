tttrlib in your language#

tttrlib is one C++ core exposed to Python, R, Java and JavaScript through a shared SWIG interface. The same objects, the same algorithms, and the same file readers are available from every language — only the surface syntax differs. Pick a language below; the tabs on this page stay in sync, so every example is shown the way you would write it.

The reference binding — installed from conda-forge/Bioconda or PyPI, with NumPy arrays throughout. This is the most heavily tested surface.

An installable R package. Arrays are native R vectors; methods are S4-style free functions, e.g. TTTR_get_macro_times(obj) rather than obj.macro_times. See the R install guide.

A self-contained JNI JAR (also shipped as an ImageJ/Fiji plugin). Arrays are Java primitives (long[], int[], double[]); large “output” getters use …_into(array) accessors. See the ImageJ guide.

A Node.js native addon (Node-API), covering the same surface as Python. Arrays are TypedArrays, and 64-bit values — macro times above all — are BigUint64Array rather than Float64Array, because a JavaScript number stops being exact at 253. std::vector and std::map become TypedArrays and plain objects, mirroring Python’s list and dict. Methods are available under both their C++ names and camelCase aliases. See tttrlib for JavaScript (Node.js).

Tip

No code required? The Java binding also ships as an ImageJ/Fiji plugin that opens PTU/HT3/SPC confocal files and reconstructs intensity, FastLifetime, phasor, and Number & Brightness images directly in Fiji — drop a single JAR into Fiji.app/plugins. See tttrlib for Java & the ImageJ/Fiji plugin.

Install#

# conda (recommended; pulls the compiled core)
mamba install -c conda-forge -c bioconda tttrlib

# or from PyPI
pip install tttrlib

# conda
mamba install -c conda-forge -c tpeulen r-tttrlib

Building from source is described in tttrlib for R (r-tttrlib).

The easiest install is to download the ready-built plugin JAR tttrlib_imagej-<version>.jar from the latest GitHub release (under Assets). It bundles the native library for Linux, macOS (Intel + Apple Silicon), and Windows — drop it on the class path, or into Fiji.app/plugins to use it as an ImageJ plugin. Details in tttrlib for Java & the ImageJ/Fiji plugin.

npm install tttrlib

Or build the addon from the repository:

cmake -S . -B build -DBUILD_JAVASCRIPT_INTERFACE=ON
cmake --build build -j

Needs Node ≥ 12.17 and SWIG ≥ 4.2. Because Node-API has a stable ABI, one binary per platform serves every later Node version without a rebuild.

Load a file and inspect the photon stream#

Every binding reads the same raw formats (PicoQuant PTU/HT3, Becker & Hickl SPC, …) and exposes the same per-photon arrays.

import tttrlib

data = tttrlib.TTTR("bh_spc132.spc", "SPC-130")
print(data.size)                         # number of photons
print(data.macro_times[0])               # first macro time
print(data.micro_times[0])               # first micro time
print(data.get_used_routing_channels())  # e.g. [0, 1, 8, 9]

library(tttrlib)

data <- TTTR("bh_spc132.spc", "SPC-130")
TTTR_size(data)                        # number of photons
TTTR_get_macro_time_at(data, 0L)       # first macro time
TTTR_get_micro_time_at(data, 0L)       # first micro time
TTTR_get_used_routing_channels(data)   # e.g. c(9, 8, 0, 1)

macro <- TTTR_get_macro_times(data)    # full vector

import io.github.fluorescencetools.tttrlib.*;

TTTR data = new TTTR("bh_spc132.spc", "SPC-130");
long n = data.size();                       // number of photons
System.out.println(data.get_macro_time_at(0));
System.out.println(data.get_micro_time_at(0));

long[] macro = new long[(int) n];           // fill a preallocated array
data.get_macro_times_into(macro);

int[] channels = new int[256];
int nCh = data.get_used_routing_channels_into(channels);

const tttrlib = require('tttrlib');

const data = new tttrlib.TTTR('bh_spc132.spc', 'SPC-130');
console.log(data.size());                    // number of photons
console.log(data.macroTimes[0]);             // BigInt: 56916n
console.log(data.microTimes[0]);             // first micro time
console.log(data.getUsedRoutingChannels());  // Int8Array [0, 1, 8, 9]

// Macro times exceed 2**53, so reduce them as BigInt, not as Number.
const total = data.macroTimes.reduce((a, b) => a + b, 0n);

Build a micro-time (decay) histogram#

hist, time_axis = data.get_microtime_histogram(micro_time_coarsening=1)
print(len(hist), max(hist))

# multi-output call returns list(NULL, histogram, time_axis)
hist <- TTTR_get_microtime_histogram(data)[[2]]
c(length(hist), max(hist))

double[] hist = new double[data.get_number_of_micro_time_channels()];
data.get_microtime_histogram_into(hist, new VectorInt32(), 1);

const [hist, timeAxis] = data.getMicrotimeHistogram(1);
console.log(hist.length, Math.max(...hist));

Reconstruct a FLIM image (CLSM)#

Confocal image reconstruction and the fluorescence-lifetime (mean micro time) image are shared across all three bindings.

img = tttrlib.CLSMImage(data, channels=[0], fill=True)
intensity = img.get_intensity()           # (frames, lines, pixels)
lifetime  = img.get_mean_micro_time(data)  # FastLifetime image
phasor    = img.get_phasor(data)           # g/s coordinates

img       <- CLSMImage(data, CLSMSettings(), NULL, TRUE, c(0L))
intensity <- CLSMImage_get_intensity(img)
lifetime  <- CLSMImage_get_mean_micro_time(img, data)
phasor    <- CLSMImage_get_phasor_v(img, data)  # g/s, interleaved

VectorInt32 ch = new VectorInt32(); ch.add(0);
CLSMImage img = new CLSMImage(data, new CLSMSettings(), null, true, ch);
int nPix = img.getN_frames() * img.getN_lines() * img.getN_pixel();

int[] intensity = new int[nPix];
img.get_intensity_into(intensity);
double[] lifetime = new double[nPix];
img.get_mean_micro_time_into(lifetime, -1.0, 2, false, false);

const img = new tttrlib.CLSMImage(data);
const intensity = img.getIntensity();      // flat Uint32Array...
intensity.shape;                            // ...with [frames, lines, pixels]
const lifetime = img.getMeanMicroTime(data);

How consistent are the bindings?#

Because they all share the same C++ core, they return identical numbers on the same input. This is enforced in CI by a cross-language reference test suite (test/python/*/test_*cross_language*.py, test/r/test_*.R, test/java/*Test.java, test/js/cross_language_reference.test.mjs) that asserts the same canonical values — photon counts, routing channels, correlator curves, burst results, micro-time histograms, CLSM intensity / lifetime / phasor, decay-fit results (fit23–fit26), and PDA histograms — from every binding.

tools/check_swig_multilang.sh additionally generates all four wrappers from the shared interface fragments on every change, so a Python-only construct leaking into the language-neutral core is caught without a native build.

Note

The Python binding is the most mature and has the broadest test suite. JavaScript wraps the same full surface and is verified against the same reference values. R and Java expose the same core, also verified against those values, but wrap a smaller slice of the API. If you hit a gap, please open an issue.

Note

Two things are unavailable outside Python, for the same reason in both cases: SWIG generates no directors for the R and JavaScript backends, so PdaCallback cannot be subclassed there (PDA’s built-in models are unaffected). And every binding is synchronous — in a Node.js server, put tttrlib calls in a worker_thread, as examples/js/ptu-webapp/ does.
