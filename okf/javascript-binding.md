# Summary

The fourth language binding for tttrlib, alongside Python, R and Java. Generated
by `swig -javascript -napi` from the **same** interface fragments in `ext/python/`
that produce the other three, so the numbers cannot drift between them.[^prd-016]

Committed as `b4e8e7d0` on 2026-08-06.

# Scope

Unlike R and Java, which wrap a subset, the `%include` list in `ext/js/tttrlib.i`
is **identical** to `ext/python/tttrlib.i`'s. A subset was not cheaper: the shared
fragments are one dependency graph, and the guards a subset needs are most of the
guards the whole needs.

| Area | Wrapped |
|---|---|
| Core, I/O, header, selections | yes |
| Burst search and filtering | yes |
| Correlation (FCS/FCCS) | yes |
| CLSM / FLIM imaging, super-resolution, localization | yes |
| HMM decoding, neural net, surrogate | yes |
| PDA, decay convolution, decay fits | yes |
| Photon simulator | yes |
| DataStore, CSV, histograms, registry, TIFF | yes |
| Columnar HDF5 (`Hdf5Table.i`) | **no** — see [open items](/open-items.md) |

# Conventions

Five things a Python user has to relearn. All are consequences of JavaScript, not
choices made for their own sake.

| Convention | Why |
|---|---|
| 64-bit values are `BigUint64Array` / `BigInt64Array`, never `Float64Array` | A JavaScript number is exact only below 2^53; macro times exceed it. A `Float64Array` input is rejected rather than silently rounded. |
| ND results are flat, row-major, with a `shape` property | JavaScript has no ND array. The same form is accepted back as input, as are nested arrays and `{data, shape}`. |
| `std::vector` → TypedArray, `std::map` → plain object | The Node-API `std_vector.i` / `std_map.i` produce opaque proxies (as Java's do); Python produces lists and dicts. Map keys become strings. |
| Two names per method, and `%attribute` members are properties | `get_macro_times` and `getMacroTimes` both work; `header.micro_time_resolution` is a property, exactly as in Python. |
| Everything is synchronous | A 200 MB read blocks the event loop, so server code belongs in a `worker_thread`. |

# Build

```bash
npm install --prefix ext/js/pkg          # Node-API headers come from npm
cmake -S . -B build -DBUILD_JAVASCRIPT_INTERFACE=ON
cmake --build build -j
node --test test/js/
```

Requires SWIG ≥ 4.2 (the Node-API backend landed there) and Node ≥ 12.17.
Node-API's stable ABI means one binary per platform serves every later Node
without a rebuild — the reason this targets `-napi` rather than the V8 backend.
