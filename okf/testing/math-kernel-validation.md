# `modules/math` — validation register

Every kernel in `modules/math` has been A/B-tested against an **independent**
reference implementation — sklearn, scipy, scikit-image, numpy, hmmlearn,
filterpy, Random123 / pcg32 known answers. The A/Bs are permanent tests, not
one-off scripts, and each header carries a `// Validation: A/B-TESTED <date>
-- ...` block after its include guard that names the reference and the test.
This file is the register those blocks point at.

Rule applied (user, 2026-08-11): *a method reimplemented in-tree is A/B'd
against the reference implementation and the A/B is kept as the acceptance
test.*

**ChiSurf is not a reference (user, 2026-08-19: "no chisurf as ref, not
stable").** It is a moving target that this library is also the upstream of,
so "the two agree" says only that two things which change together still
agree — and where a kernel began as a port of it, "bit-exact with ChiSurf" is
a statement about a snapshot, not about the mathematics. Every row that rested
on ChiSurf has been replaced by the upstream that was already checking the
same claim (scipy, scikit-learn, filterpy) and the ChiSurf tests are deleted,
not merely demoted. Being a port of ChiSurf is a fact about a kernel's
history; it is not evidence that it is right.

## How to run

```bash
python -m pytest test/python/misc/test_math_ab_clustering.py \
                 test/python/misc/test_math_ab_imaging.py \
                 test/python/misc/test_math_ab_probabilistic.py \
                 test/python/misc/test_math_ab_numerics.py
# 72 tests, 209 subtests, ~17 s on 2026-08-17. Reference libraries are optional
# imports; a missing one skips its class visibly. test_math_ab_numerics.py
# compiles test/cpp/ab_numerics_harness.cpp once (skips without a compiler).
```

Recorded references: `test/data/reference/math_ab_probabilistic_reference.npz`
(hmmlearn 0.3.3 + filterpy 1.4.5, generated by
`test/python/misc/gen_math_ab_probabilistic_reference.py` in a scratch venv so
neither package enters the project environment; inputs are stored beside
outputs), and the pre-existing `watershed_skimage_reference.npz`,
`kmeans_chisurf_reference.npz`, `kalman_chisurf_reference.npz`.

## What the A/B found

* **`Random.h` PCG engine was not PCG.** `pcg_deterministic_u32` wrote the
  xorshift as `((state >> 18) ^ (state >> 27)) >> 27`; XSH-RR is
  `((state >> 18) ^ state) >> 27`. The pre-rotation word had 19 live bits, so
  every output had 13 zero bits in a rotating window and per-bit P(1) was
  0.22–0.37. Fixed 2026-08-17 (one token). Reach: `TTTR_RNG_ENGINE=pcg`, and the
  engine `selected_engine()` picks when `TTTR_RNG_DETERMINISTIC` is off with no
  engine named — never the Philox default, so no recorded fixture depended on
  the old stream. The Python binding needs a rebuild to pick the header change up.
* **`Random.h` `mt19937` was a name without an engine** — every streaming draw
  was Philox whatever the env said. Implemented 2026-08-17 (std::mt19937, numpy
  RandomState-identical); `deterministic` keeps its documented Philox fallback.
* **HDBSCAN vs sklearn end to end differs only on MST ties** — sklearn sorts
  its MST with unstable `np.argsort`, so equal-weight edges merge in an
  irreproducible order; feeding either side's tree to the other's downstream is
  exact 36/36. Not a kernel difference; tttrlib's total edge order is the reason
  its own answer is reproducible.
* **`quadpr_bound` is not KKT-correct**, as its header already says, and the
  A/B pins the shape of that: equal to scipy whenever the sweep lands on a KKT
  point, feasible and never below the true minimum otherwise.
* **Two references are not references.** `skimage.restoration.wiener` is a
  different estimator from `wiener_deconvolve` (Laplacian-weighted balance,
  circular grid); ChiSurf's `mem.py` returns a value and a gradient of two
  different objectives. Both documented in the test docstrings rather than
  compared with a loose tolerance.
* **k-means `tol` differs from sklearn's** (Frobenius shift vs squared shift
  scaled by variance); the comparison runs both to strict convergence.
* **NNLS `x` is non-unique** on ill-conditioned / underdetermined designs
  (raw diffs up to 3e5 while residuals agree to 1e-10 and KKT holds); those
  cases pin residual + KKT only.
* **scipy's bounded Nelder-Mead stalls** short of the constrained optimum on
  both bounded cases; ours reaches it. Reference quirk.
* SWIG `VectorDouble` results (`r.p`, `maxent_invert`) must be copied while the
  owning result is alive — `np.asarray(f(...).p)` on a temporary produced
  garbage. Binding footgun, not a kernel issue.

## Keeping this current

A new kernel in `modules/math` gets a row here, a `// Validation:` block in its
header, and a test in the matching `test_math_ab_*.py` before it is called
done. If a kernel changes so a row's metric no longer holds, the test fails —
update the row with what changed and why, or fix the kernel; never loosen the
tolerance to make it pass.
